# ADR-0013: Command-паттерн для undo/redo на уровне модели

- **Статус:** Accepted
- **Дата:** 2026-08-18
- **Связанные документы:** [`FS.md`](../../FS.md) §4.1, §9.2; [`TODO.md`](../../TODO.md) §5.1

## Контекст

`UndoRedoStack` (FS §9.2) оперирует парами `(action, data)` на уровне UI.
Это не гарантирует согласованности отката с XML-моделью `Document`
(вставка формулы затрагивает и `body`, и `named-objects`, и нумерацию).
Для надёжного undo/redo нужно перенести логику на уровень модели.

## Решение

1. **Command-паттерн:** каждая операция над `Document`
   (`InsertText`, `InsertFormula`, `InsertTable`, `DeleteBlock`,
   `SetStyle`, `InsertReference`…) — класс-команда с методами
   `execute()` / `undo()` / `redo()`.

2. **Стек команд** (адаптированный `UndoRedoStack`, MAX_HISTORY=100):
   - `execute()` — применение к `Document` + push в undo-стек;
   - `undo()`/`redo()` — инвертирование/повтор без потери консистентности
     (в т.ч. пересчёт `named-objects` и нумерации через ADR-0011).

3. **UI создаёт команды** (не мутирует модель напрямую) — меню «Правка →
   Отменить/Повторить» лишь вызывает стек.

4. **Сериализация в `.sdoc`** не зависит от стека — undo/redo работает
   поверх актуального состояния `Document`.

## Последствия

- Undo/redo надёжно синхронизирован с моделью и форматом.
- Чистое разделение «модель ↔ UI» упрощает тестирование ядра.
- Увеличивает объём ядра, но устраняет хрупкость UI-стека из FS §9.2.
