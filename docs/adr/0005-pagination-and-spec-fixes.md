# ADR-0005: Пагинация `get_page_count()` и исправления спецификаций

- **Статус:** Accepted
- **Дата:** 2026-08-18
- **Связанные документы:** [`FS.md`](../../FS.md) §4.1, §7.1; [`TZ.md`](../../TZ.md) §2.4

## Контекст

1. **`Document.get_page_count()` неопределён.**
   В поточном WYSIWYG-редакторе количество страниц зависит от рендеринга
   (шрифт, поля, размер окна) и не может быть вычислено без контекста.

2. **В FS.md найдены дефекты псевдокода и структуры тестов:**
   - сломанный f-string в `PreviewWidget._render_section` (FS §4.10);
   - дублирование `self.validation_label = QLabel()` (FS §4.8);
   - мальформированная структура раздела тестов `tests/` (FS §7.1);
   - лишний символ «草案» в строке статуса документа.

## Решение

1. **Пагинация откладывается.** `get_page_count()` и `get_page_count`/счётчик
   страниц в статус-баре исключаются из API ядра; номер страницы считается
   только в UI по фактическому рендерингу (`QTextDocument.pageCount()` /
   `QTextEdit.document().pageCount()` при заданном `pageSize`).
   В API ядра оставить только `get_word_count()`.

2. **Исправить дефекты FS.md** (см. сами правки в файле):
   - `_render_section` — валидный псевдокод;
   - убрать дубль `validation_label`;
   - нормализовать структуру `tests/` (§7.1);
   - убрать «草案», заменить на `Draft`.

## Последствия

- Ядро не зависит от UI-пагинации; страницы считаются там, где есть рендеринг.
- Спецификация становится консистентной и готовой к реализации.
