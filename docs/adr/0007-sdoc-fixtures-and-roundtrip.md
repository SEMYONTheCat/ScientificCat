# ADR-0007: Фикстуры `.sdoc` и gold-тесты на round-trip

- **Статус:** Accepted
- **Дата:** 2026-08-18
- **Связанные документы:** [`FS.md`](../../FS.md) §2, §7; [`TZ.md`](../../TZ.md) §6 (критерий 1); [`ADR-0004`](0004-sdoc-format-and-module-structure.md)

## Контекст

Формат `.sdoc` описан XSD-планом и рукописным образцом, но не имеет
эталонных файлов и автоматической проверки целостности. Критерий приёмки №1
(«открывается и сохраняется без потери данных») без эталонов не проверяем.

## Решение

1. **Каталог `tests/fixtures/`** с эталонными `.sdoc`-файлами:
   - `minimal.sdoc` — пустой/минимальный документ;
   - `cyrillic.sdoc` — кириллица в заголовках, абзацах, метаданных;
   - `formulas.sdoc` — inline и display формулы, греческие буквы;
   - `table.sdoc` — таблицы с объединением ячеек;
   - `bibliography.sdoc` — записи BibTeX, цитаты, `named-objects`;
   - `resources.sdoc` — base64-вложения (изображения).

2. **Gold-тесты на round-trip:** `test_roundtrip.py` — для каждой фикстуры
   выполняется «parse → serialize → parse» и сравнивается семантическая
   эквивалентность (структура, атрибуты, LaTeX-исходники формул, тексты).

3. **Property-based проверки** для `generate_id()` (уникальность, префиксы)
   через `hypothesis` (опциональная зависимость для тестов).

## Последствия

- Формат `.sdoc` получает исполняемый «контракт», а не только описание.
- Регрессии парсера/сериализатора ловятся автоматически.
- Фикстуры служат и демо-материалом, и базой для бенчмарков (ADR-0009).
