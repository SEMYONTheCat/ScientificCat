# ADR-0008: Инструментарий качества (lint, типы, формат, CI)

- **Статус:** Accepted
- **Дата:** 2026-08-18
- **Связанные документы:** [`TODO.md`](../../TODO.md) §1.1; [`FS.md`](../../FS.md) §5

## Контекст

В TODO упомянуты `flake8`/`black`, но набор инструментов качества и его
конфигурация не зафиксированы. Без этого контрибьюция и CI нестабильны.

## Решение

1. **Единый инструментарий, сконфигурированный в `pyproject.toml`:**
   - `ruff` — линтер и форматтер (замена `flake8`+`black`);
   - `mypy` — статическая типизация (strict для `core/`);
   - `pre-commit` — хуки: ruff, mypy, формат, секреты;
   - `pytest` + `pytest-qt` — юнит и GUI-тесты;
   - `hypothesis` — property-based тесты (см. ADR-0007).

2. **CI-гейт (GitHub Actions / GitLab CI):**
   - на каждый PR: `ruff check`, `mypy`, `pytest` (core + ui smoke);
   - ночной запуск: бенчмарки (ADR-0009), полный GUI-прогон на матрице ОС.

3. **Строгие правила для `core/`, ослабленные для `ui/`** (порог mypy),
   чтобы не блокировать итеративную разработку интерфейса.

## Последствия

- Единообразный код и раннее обнаружение ошибок.
- Качество встроено в процесс, а не «постфактум».
- Требуется согласование порогов в `pyproject.toml` на этапе реализации.
