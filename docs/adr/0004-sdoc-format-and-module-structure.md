# ADR-0004: Формат `.sdoc`, XSD-схема и структура модулей формул

- **Статус:** Accepted
- **Дата:** 2026-08-18
- **Связанные документы:** [`FS.md`](../../FS.md) §1.1, §2.1, §4.2, §4.3; [`TZ.md`](../../TZ.md) §2.1

## Контекст

1. **Формат `.sdoc` не имеет машиночитаемого источника истины.**
   Схема описана только рукописным образцом XML (FS §2.1), при этом во всех
   API ссылаются на `assets/schema/sdoc-v1.0.xsd`, которого не существует.
   Без XSD формат нестабилен и не проходится валидация (ТЗ §4.3).

2. **Противоречие структуры модулей.** В FS §1.1 в `core/` есть только
   `formula_engine.py`, а API §4.2 описывает класс `Formula` в `core/formula.py`.

## Решение

1. **XSD — единственный источник истины формата `.sdoc`.**
   - Создать `assets/schema/sdoc-v1.0.xsd`.
   - План схемы (детально) — см. раздел в FS.md; охватывает элементы:
     `metadata`, `styles`, `body` (`section`, `heading`, `paragraph`, `run`,
     `formula`, `list`, `table`), `bibliography`, `named-objects`, `resources`.
   - `XMLParser._validate_schema()` валидирует через `lxml` по этой схеме.
   - Правила нумерации и именования ID (FS §2.2–2.3) описываются в схеме
     через `xs:pattern`/документацию, а исполняются в сериализаторе.

2. **Структура `core/` — два модуля формул:**
   ```
   core/
   ├── formula.py          # модель Formula (latex, type, id, number)
   └── formula_engine.py   # FormulaEngine: конвейер рендеринга (ADR-0002)
   ```
   - `Formula` — модель данных (без рендеринга).
   - `FormulaEngine` — сервис рендеринга/валидации.
   - Оба файла включаются в структуру каталогов FS §1.1.

## Последствия

- Формат стабилен и машинно-валидируем.
- Модель данных отделена от движка рендеринга — проще тестировать.
- Структура каталогов в FS.md приводится в соответствие с этим ADR.
