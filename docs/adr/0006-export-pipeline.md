# ADR-0006: Система экспорта (PDF, DOCX, HTML, LaTeX)

- **Статус:** Accepted
- **Дата:** 2026-08-18
- **Связанные документы:** [`FS.md`](../../FS.md) §4.5; [`TZ.md`](../../TZ.md) §2.4; [`ADR-0002`](0002-rendering-pipeline.md)

## Контекст

Модуль `Exporter` (FS §4.5) — один из самых рискованных: требования экспорта
(ТЗ Р-01…Р-05) покрывают четыре разных формата, каждый со своей моделью
встраивания формул. Спецификация задаёт общий каркас, но не фиксирует:

- как именно встраиваются формулы в каждый формат (SVG/PNG/HTML/LaTeX-код);
- используется ли реальный LaTeX-компилятор (TeX Live) или программный рендер;
- единую схему конверсии `Document` → целевой формат.

Без этого решения экспорт реализуется ad hoc и переделывается.

## Решение

**1. Единый конвейер экспорта с общим промежуточным представлением.**
Вводится нейтральный промежуточный слой (Intermediate Representation, IR) —
простая структура блоков, в которой формулы представлены LaTeX-исходником
(а не отрендеренными картинками). Каждый экспортёр конвертирует именно IR:

```
Document → IR (блоки: текст, заголовки, формулы-inline/display,
               списки, таблицы, библиография, ресурсы)
                 │
   ┌─────────────┼──────────────┬──────────────┐
   ▼             ▼              ▼              ▼
 PDF           DOCX           HTML           LaTeX
 (QPrinter)    (python-docx)  (KaTeX CDN)    (.tex)
```

Формулы в IR хранятся как `latex: str` + `type`; рендер в SVG/PNG происходит
**в самом экспортёре** на этапе вывода (по ADR-0002).

**2. Экспорт PDF — через `QPrinter` с SVG-встраиванием формул.**
- HTML/текст собирается из IR; формулы рендерятся в SVG (MathJax-svg).
- Компоновка на страницу выполняется через `QTextDocument` с заданным
  `pageSize`, печать — `QPrinter.PdfFormat`.
- Кириллица обеспечивается явным указанием шрифтов в HTML.

**3. Экспорт DOCX — `python-docx`, формулы как PNG-изображения.**
- Текст/структура → параграфы `python-docx`.
- Формулы (inline и display) → `InlineShape` PNG через `latex_to_png(dpi=300)`.
- Нативная OMML-математика НЕ используется (сложность и риск для v1.0) —
  это фиксируется как сознательное ограничение, подлежащее пересмотру в v2.

**4. Экспорт HTML — с KaTeX CDN.**
- Из IR собирается HTML; формулы — `<span class="katex">latex</span>`.
- Подключается `katex.min.css/js` (самостоятельная HTML-страница, не
  зависящая от приложения). Подходит для публикации.

**5. Экспорт LaTeX — прямой вывод `.tex`.**
- IR → текст с формулами в математическом режиме
  (`$...$` для inline, `\[...\]` для display).
- Преамбула подключает `amsmath`, `amsfonts`, `inputenc`(utf8) и
  `babel`/`fontenc` для кириллицы.
- **Компиляция в PDF через TeX Live вынесена из v1.0** (отдельный вызов
  `xelatex`/`pdflatex` — опциональная интеграция, см. дорожную карту).

## Последствия

- Экспорт изолирован от внутреннего представления и легко тестируется
  (gold-тесты на IR → формат).
- Один источник рендера формул (ADR-0002) используется всеми экспортёрами.
- DOCX без OMML и PDF без TeX Live — зафиксированные компромиссы v1.0,
  документированные для будущей версии.
- Требуется модуль `core/ir.py` (промежуточное представление) или его
  эквивалент в составе `core/exporter.py` — уточнить при реализации.
