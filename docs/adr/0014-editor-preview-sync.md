# ADR-0014: Событийная синхронизация Editor ↔ Preview

- **Статус:** Accepted
- **Дата:** 2026-08-18
- **Связанные документы:** [`FS.md`](../../FS.md) §4.7, §4.10; [`TZ.md`](../../TZ.md) §2.4, §4.1; [`ADR-0009`](0009-formula-benchmarks.md)

## Контекст

Превью должно обновляться в реальном времени (Р-01), но полный перерендер
всего документа на каждое нажатие клавиши противоречит метрике 60 fps
(ТЗ §4.1). Нужен управляемый поток обновлений Editor → Preview.

## Решение

1. **Единый сигнал изменений** от `EditorWidget` (QTextEdit) с
   **debounce через `QTimer`** в GUI-потоке (по ADR-0003): изменения
   накапливаются ~300 мс, затем генерируется событие.

2. **Инкрементальное обновление через IR:** из `Document` строится
   промежуточное представление (ADR-0006); превью получает только
   изменённые блоки, а не весь документ.

3. **Поток данных:**
   ```
   Editor(QTextEdit) → debounced signal → Document → IR update
        → PreviewWidget(QWebEngineView) → KaTeX-рендер затронутых блоков
   ```

4. **Метрика 60 fps** достигается ограничением числа KaTeX-рендеров
   за кадр; тяжёлые формулы кэшируются по LaTeX-хэшу.

## Последствия

- Превью отзывчивое без перерасхода ресурсов.
- Метрики из ADR-0009 интерпретируются в терминах инкрементального обновления.
- Требует тесной связи `EditorWidget`, `Document` и `PreviewWidget`.
