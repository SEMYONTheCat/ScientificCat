# ADR-0011: Перекрёстные ссылки и сноски

- **Статус:** Accepted
- **Дата:** 2026-08-18
- **Связанные документы:** [`FS.md`](../../FS.md) §2.1, §2.3; [`TODO.md`](../../TODO.md) §5.4; [`ADR-0010`](0010-floating-objects-and-captions.md)

## Контекст

`named-objects` в формате предназначены для ссылок, но механизм вставки
«см. уравнение (2)» и сносок не описан. Без него научно-редакторская
функциональность (критерий автоперенумерации) не реализуется.

## Решение

1. **Элемент ссылки в абзаце:**
   ```xml
   <run text="см. "/><reference id="ref1" target="eq2"/><run text=""/>
   ```
   - `target` указывает на ID объекта из `named-objects`.
   - Номер/метка («уравнение (2)», «таблица 1», «раздел 1.1») вычисляются
     при рендере из `named-objects` — поэтому авто-обновляются.

2. **Сноски:**
   ```xml
   <footnote id="fn1"><run text="Текст сноски"/></footnote>
   ```
   - Нумерация сносок сквозная, авто-обновление при вставке/удалении.

3. **Разрешение ссылок** выполняется единым сервисом `ReferenceResolver`
   на уровне `Document`; отрендеренные подписи подставляются во все
   экспортёры (через IR, см. ADR-0006) и в превью.

4. **Авто-нумерация** формул/таблиц/рисунков/разделов (FS §2.3) — через
   пересчёт `named-objects` и `section.number` при изменении структуры.

## Последствия

- Появляются рабочие перекрёстные ссылки и сноски.
- Зависит от регистрации объектов (ADR-0010) и общего IR для экспорта.
- Требует обновления XSD-плана (FS §2.4) и парсера/сериализатора.
